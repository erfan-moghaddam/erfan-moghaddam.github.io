01 / Project field notes

MyNexPark

Accounts, vehicles, wallets and payments. One native Android experience for the everyday side of smart parking.

Consumer Android applicationPublished on Café Bazaar
Project field notes

01

Overview

MyNexPark is the consumer Android application in the NexPark parking ecosystem. I develop the native Android experience, connecting account, vehicle and payment journeys to the underlying services.

02

The problem

Parking is a physical task, but the supporting digital steps involve several systems. Account access, vehicle information and wallet actions need to remain understandable while requests are in flight or fail.

03

The solution

A Compose interface with reusable components, explicit screen state and a separated networking layer. The application brings the important flows together without asking users to understand the system behind them.

04

My role

Android development · Kotlin & Jetpack Compose

05

Technologies

Kotlin · Jetpack Compose · Hilt · Retrofit · DataStore

06

Technical decisions

Hilt supplies dependencies, Retrofit handles API integration, and DataStore persists session preferences. ViewModels and Kotlin Flow connect asynchronous work to Compose state. These choices are visible in the source; this is a summary rather than a complete architecture diagram.

07

Features

  • Account access and session handling
  • Vehicle management
  • Wallet and payment journeys
  • Biometric confirmation for selected actions
  • Localized Compose interfaces
08

The challenge

Keeping session, loading and network failure states predictable across connected user journeys. Separating these responsibilities makes the UI easier to maintain.

09

Outcome

The Android application is publicly available on Café Bazaar. No adoption, revenue or performance figures are claimed here.

10
